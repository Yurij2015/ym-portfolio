## Розробка та інтеграція API

Маршрут: /services/api-development

Створюю API, через які мобільні застосунки, фронтенди й партнерські сервіси можуть отримувати та оновлювати дані, виконувати пошук і запускати фонові операції. Разом із реалізацією готую документацію запитів, відповідей і помилок, щоб інша команда могла підключити свій застосунок. Якщо API вже працює, планую зміни з урахуванням клієнтів, які ним користуються.

### Що ви отримуєте

- Ендпоінти для потрібних операцій, наприклад пошуку записів, оновлення даних або запуску фонового завдання
- Документація запитів, відповідей і помилок
- Тести та приклади запитів для команди, яка підключатиметься

### Порядок роботи

1. **Контракт API.** Описуємо, хто викликає API, які дані й операції потрібні, як працюють доступ і ліміти.
2. **Реалізація.** Пишу ендпоінти, перевірки доступу, тести й документацію.
3. **Перевірка з клієнтом.** Проганяємо API разом із клієнтським застосунком або набором тестових запитів.

### API під конкретних клієнтів

У VetSpace один Laravel API обслуговує дві частини продукту: публічний каталог через GraphQL і CRM через REST. У NetPostPanel через API можна замовити генерацію та переклад контенту й отримати результат одразу або з колбеком. Ці приклади показують, чому ще до розробки потрібно визначити, хто звертатиметься до API та як довго виконуватимуться його операції.

Окремий приклад — клієнтський маркетплейс, для якого я писав REST API з авторизацією через Sanctum і документацією Swagger. Через нього працюють оголошення, замовлення, чат і тікети підтримки, тож правила доступу й обробка помилок є частиною кожного сценарію.

Тому роботу починаю з опису операцій, доступних даних і відповідей, які має отримати клієнтський застосунок. Для довгих задач передбачаю фонове виконання та спосіб дізнатися результат. На основі цього готую реалізацію, документацію й тести.

Щоб оцінити вашу задачу, достатньо описати потрібні операції та додати приклад даних. Якщо API вже існує, допоможе й поточна документація. Вартість групи пов’язаних операцій із документацією та тестами починається від $1 800.

### Запитання

**Чи можна доопрацювати наявний API?**

Так. Спочатку дивлюся поточний контракт і те, хто ним користується, а потім планую сумісні зміни або нову версію.

**Чи завжди потрібен REST?**

Ні. Формат залежить від клієнтів і операцій. Якщо REST уже працює й підходить, міняти його немає сенсу.

## Адмін-панелі для PHP та Laravel-застосунків

Маршрут: /services/admin-panels

Розробляю адмін-панелі, у яких команда може працювати з клієнтами й замовленнями, редагувати контент і переглядати звіти. Залежно від застосунку та потрібних екранів використовую Filament, Flowbite на Tailwind або AdminLTE на Bootstrap. Це може бути як нова панель, так і поступова заміна старої адмінки.

- Ролі, права доступу й перевірки операцій із даними
- Тести основних дій і коротка інструкція для користувачів

### Порядок роботи

1. **Розбір роботи команди.** Дивимося, що працівники роблять зараз і які дані потрібні на кожному екрані.
2. **Вибір інструмента й розробка.** Обираю Filament, Flowbite чи AdminLTE під наявний код, потім створюю форми, фільтри й бізнес-дії.
3. **Перевірка з користувачами.** Працівники пробують панель, я виправляю незручності й права доступу.

### Приклади з проєктів

У DigiSpace я поступово переношу екрани зі старої адмінки на Inertia та Vue до Filament. Обидві панелі працюють поруч, а в новій уже можна редагувати контент, переклади й SEO-метадані. Filament використовую і в DigiPulse, де через нього керують моніторами, контактами та правилами сповіщень.

Для інтерфейсів на Vue та Nuxt працюю також із Flowbite. На ньому побудовані NetPostPanel і панель клініки VetSpace, а серед клієнтських проєктів — адмінка маркетплейсу з користувачами, оголошеннями й замовленнями та сервіс для фотографів із галереями й пакетами послуг.

Маю досвід і з AdminLTE: на ньому я робив дві панелі для Laravel-застосунків. Одна за розкладом отримує дані через зовнішній API й дає агенції змогу переглядати статистику та витрати й експортувати їх. Інша керує збором і фільтрацією даних із соцмережі через черги задач.

У кожному з цих випадків обсяг роботи визначають щоденні дії команди: які дані треба створювати й редагувати, як їх шукати та які операції потребують підтвердження. Тому для оцінки найкраще показати поточні екрани або таблиці й розповісти, що доводиться робити вручну.

Вартість набору пов’язаних екранів починається від $1 600. Якщо потрібні імпорт, звіти чи нестандартні операції, враховую їхню складність у загальній оцінці.

### Запитання

**Filament, Flowbite чи AdminLTE?**

Filament підходить, коли застосунок на Laravel, а панель складається з типових екранів зі списками, формами, фільтрами й ролями. Flowbite беру, коли потрібен власний вигляд чи нестандартні екрани або коли фронтенд окремий, на Vue чи Nuxt. AdminLTE доречний, якщо проєкт уже на Bootstrap або в ньому є адмінка на AdminLTE, яку треба доробити.

**Чи можна додати Filament у наявний Laravel?**

Так, якщо сумісні версії, моделі й авторизація. Ресурси можна додавати по одному, не чіпаючи решту застосунку.

**Що робити, якщо бекенд не на Laravel?**

Тоді Filament не підійде. Панель на Flowbite або AdminLTE можна вбудувати в наявний PHP-застосунок або зробити окремою, з доступом до даних через API. Другий варіант додає інтеграційну роботу.

Ціна від: $1600. Після визначення екранів, ролей і нестандартних дій.
